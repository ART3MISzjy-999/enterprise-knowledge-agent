# 需求

## 用户

面向需要查询企业制度、内部FAQ或产品说明的员工，以及核查回答依据的评审者。员工可以一次提出多个问题，也可以在后续对话中补充身份、适用地点或其他条件。

## 目标

依据给定资料回答问题，提供可核查的文档编号和原文片段。真实模型根据工具反馈决定是否检索、补充检索、读取原文、向用户澄清或结束；不能以预设问题分类替代模型决策。

对于混合问题，应保留能确认的部分，说明未被资料支持的部分；对于冲突制度，应交叉读取并请求确认适用依据，不能仅按日期选择。工具失败或预算耗尽时，应明确说明未完成。

## 范围

输入为企业制度或产品问题，以及可选的用户/助手历史消息。数据为8篇合成制度与FAQ，包含doc_id、版本日期、适用范围和原文，另有policy_key、supersedes辅助核对同事项版本。

提供Python命令行入口、真实模型适配层、search_documents(query, top_k)与read_document(doc_id)工具、引用校验、有限执行预算、离线回归和真实Trace。支持更换符合数据格式的JSON资料及兼容接口的模型配置。

当前范围为本地知识问答，不包含实时航班/天气查询、预订或发送消息能力；不提供任意PDF/Word导入、前端页面、数据库部署或生产并发服务。

## 成功标准

| 场景 | 验收标准 |
|---|---|
| 明确答案 | 取得相关证据并引用原文，不虚构细节 |
| 文档冲突 | 读取冲突双方，展示不同规定，说明缺口并请求确认 |
| 资料外问题 | 查无依据或缺少必要能力时说明不足，不编造答案 |
| 改写后的相似问题 | 含义相同的问法仍能召回相同依据；范围扩展不自动视为同义 |
| 上下文追问 | 保留原问题，吸收用户补充或身份纠正，重新查证 |
| 工具失败 | 根据实际失败反馈合理重试或返回未完成 |
| 混合问题 | 分别处理已知与未知子问题，不整体拒答或误报全部完成 |
| 证据变化与预算 | 证据变化能影响结果，步数和工具调用数有硬上限 |
| 引用与记录 | 引用来自本轮实际工具结果；保留真实输入、实际输出及Trace，明确区分Mock与真实模型 |

真实验证材料至少覆盖正常、资料不足、工具失败，以及两种不同工具反馈后的实际后续动作。具体预期、结果和对应文件见[评估文档](03-evaluation.md)。
