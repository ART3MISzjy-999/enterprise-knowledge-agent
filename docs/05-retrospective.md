# 复盘

## 最难问题

最难的是在混合、多轮问题中持续区分“用户已经确认的事实”“资料能够证明的内容”和“仍然未知的部分”，并让模型决策、程序校验和最终回答保持一致。

报销对话暴露了这个难点：用户最初询问高铁和住宿，之后纠正身份、补充住宿一晚，系统容易只回答最后的期限，遗漏原始费用问题；过度保守时，又把已经确认的身份或晚数反复列为缺口。混合改写还会扩大范围，例如原文只规定个人网盘限制，用户却问所有个人设备，不能直接把两者当成同义。

进一步测试发现，问题并不都在模型：M18中模型已理解“我已是正式员工”，程序的有限身份提取却保留旧实习生标签；冲突校验也曾将额外的非冲突引用当作必须读取的原文，产生模糊错误，令模型反复提交直到预算耗尽。

解决方式是：按子问题分别保留证据和缺口；仅从用户消息维护带出处的有限事实账本，补充身份纠正及否定表达；将“未超过金额标准”和“最终一定可报销”分开；冲突读取校验限定到冲突集合，并向模型指出具体待核对文档。修复通过54项自动化回归、原9场景真实回归和同一混合测试集复测，结果及保留失败见[评估文档](03-evaluation.md)。

## 学习收获

- 引用存在不等于回答相关或适用，必须核对范围、条件、否定和版本关系。
- 模型理解正确也可能被程序后处理破坏，应检查完整链路，不能只看模型最后一句话。
- 混合问题应逐项回答，部分未知既不代表整段无依据，也不允许只答已知部分就宣布完成。
- 自动评分需要被审查：首次规则初筛20/20，内容审读仍找出M18失败；因此证据检查和语义审读需要并存。
- 工具故障、模型连接失败和资料不足应区别记录；一次重跑成功不能覆盖原完整轮失败。

## 下一步

1. 增加未用于提示或修复的独立保留集，覆盖更多身份纠正、否定、条件及多轮指代，并保留失败样例。
2. 继续改进用户事实与适用范围表示，减少依赖少量中文模式，同时验证不会将假设或他人身份当作本人事实。
3. 在原文可核查的前提下，让回答更直接地对应各个子问题，并增加独立语义支持检查。
4. 对连接异常、模型格式差异及提示注入开展有界、可复现的评估，报告恢复情况和重复运行结果，避免将一次通过当成长期稳定性。
